# Independent-consumer acceptance

What another application does with what this one produces.

## The corpus under test

| Corpus version  | 1                                                                     |

| Almanac release | 0.2.7                                                                 |

| Artifacts       | `specs/004-slef/validation/reference-corpus/`                         |

The hash is the identity of the exact bytes: the SHA-256 of each artifact's payload, joined in
manifest order and hashed again. A record that names a different hash is a record about different
bytes. Regenerate before every round — the generator refuses to write a corpus this application
cannot itself read back — and copy the new hash into the table above.

Each artifact's `appVersion` is the version root `package.json` declares, `major.minor.0`, and so is
the hash that identifies them. A deployed build carries `major.minor.<commit count>` instead, because
CI stamps the patch before building (`scripts/resolve-build-version.mjs`); the corpus is evidence
about the payload a consumer reads, not about which build produced it, so it is regenerated when the
declared version moves and not once per deployment.

The six artifacts, and the property each one is about:

| Artifact                   | What a consumer has to get right                              |
| -------------------------- | ------------------------------------------------------------- |
| `stock-small-hull`         | A whole small hull, every fixed mount populated.              |
| `stock-large-hull`         | The largest ordinary hull's slot set.                         |
| `named-and-identified`     | `ShipName` and `ShipIdent` carried through.                   |
| `disabled-and-prioritised` | `On: false` and `Priority: 0` are values, not absences.       |
| `engineered-grade-five`    | A completed roll with the Almanac's own modifiers.            |
| `emptied-optional-mounts`  | A build with optional mounts absent rather than empty-valued. |

## The protocol

Neither Coriolis nor EDSY is distributed in a form this repository can pin and run offline, so the
round is performed by hand, deliberately, and recorded. Nothing about the corpus leaves this machine
except the artifact being pasted into the consumer under test.

For each consumer, and for each artifact:

1. Open the consumer's own import surface (Coriolis: _Import_; EDSY: the import field).
2. Paste the artifact's file contents exactly, with no edit and no reformatting.
3. Record whether it was accepted, and whether the hull, every fitted module, each module's enabled
   state and priority, and any engineering read back as the manifest describes them.
4. Record the consumer's exact release or build identifier, taken from the consumer itself — its
   version banner or build stamp — never from memory.

A partial acceptance is a failure for the artifact, and the reason is recorded rather than
summarized. What matters to a Commander is which build did not survive, not a percentage.
